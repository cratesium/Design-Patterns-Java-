# Design Patterns

Design patterns are **reusable solutions to common problems** in software design. They are not complete code but templates that help developers structure their code in a flexible, maintainable, and scalable way.

---

## 📌 Why Use Design Patterns?

- Improve code **reusability**
- Make systems more **flexible and scalable**
- Provide **proven solutions** to common problems
- Improve communication between developers

---

## 🧩 Types of Design Patterns

Design patterns are broadly classified into three categories:

---

## 1. 🏗️ Creational Patterns

These patterns deal with **object creation mechanisms**, trying to create objects in a suitable manner.

### Examples:
- **Singleton** – Ensures only one instance of a class exists  
- **Factory Method** – Creates objects without specifying exact class  
- **Abstract Factory** – Creates families of related objects  
- **Builder** – Constructs complex objects step by step  
- **Prototype** – Clones existing objects  

---

## 2. 🧱 Structural Patterns

These patterns deal with **object composition** and relationships between classes.

### Examples:
- **Adapter** – Converts one interface into another  
- **Bridge** – Separates abstraction from implementation  
- **Composite** – Treats objects and compositions uniformly  
- **Decorator** – Adds behavior dynamically  
- **Facade** – Provides a simplified interface  
- **Flyweight** – Reduces memory usage  
- **Proxy** – Controls access to an object  

---

## 3. 🔄 Behavioral Patterns

These patterns focus on **communication between objects**.

### Examples:
- **Observer** – Notifies dependent objects of changes  
- **Strategy** – Allows switching algorithms at runtime  
- **Command** – Encapsulates requests as objects  
- **State** – Changes behavior based on state  
- **Mediator** – Reduces direct communication between objects  
- **Chain of Responsibility** – Passes requests along a chain  
- **Iterator** – Traverses elements in a collection  
- **Template Method** – Defines skeleton of an algorithm  

---

## 🧠 Key Concepts

- **Encapsulation** – Hides implementation details  
- **Abstraction** – Focuses on essential features  
- **Loose Coupling** – Reduces dependencies between components  
- **High Cohesion** – Keeps related functionality together  

---

## ✅ Advantages

- Improves **code readability**
- Encourages **best practices**
- Makes code **easier to maintain**
- Speeds up development using **proven solutions**

---

## ⚠️ Disadvantages

- Can increase **complexity**
- Overuse may lead to **unnecessary abstraction**
- Requires understanding of patterns to use effectively  

---

## 📊 Summary Table

| Category     | Focus                    | Examples |
|--------------|--------------------------|----------|
| Creational   | Object creation          | Singleton, Factory |
| Structural   | Class & object structure | Adapter, Decorator |
| Behavioral   | Object interaction       | Observer, Strategy |

---

## 📌 Conclusion

Design patterns are essential tools for writing **clean, maintainable, and scalable code**. Understanding when and how to use them is key to becoming a better software developer.
